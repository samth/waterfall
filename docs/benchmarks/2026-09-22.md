## Measurement

The comparison uses Lean 4.30.0 and plain `waterfall`, with default effort 1,000,
one Lean thread and synchronous elaboration (`-DElab.async=false`). Previous
main is `dde8f2e304c4327661f7833695082d3ce4819385`; current main is
`8d7d84bd08a756de7ee9c723169aee4091f9e3ef`. The standalone-compatible benchmark
runners and dispatchers at `f3ac34d7dfde4788075ea676604c1ab6f6cef554` ran unchanged.
Both versions received the same inputs and source resource options.

The selection contains 2,216 Software Foundations entries, 173 TIP/CLAM goals,
87 Leon goals, 13 MiniF2F induction goals, and the established 156 VProver goals.
Fourteen SF entries are executable definitions rather than theorem tasks. They
remain in the raw results as unsupported entries and are excluded from the
2,631-goal denominator. The VProver selection table has SHA-256
`6d3bbab3f5389473f0f13d52d2f0efd5c0f7f2f8814774e0cc6fb7b92f2c284d`.

The existing harness replaces proofs while retaining the source theory.
Preceding or imported benchmark lemmas can be admitted assumptions. Consequently,
these counts measure proving individual goals in that context, rather than
constructing all of each source development automatically.

The configured cluster hosts were `gh` and `kj`. Each SF discovery/timing process
had a cap of 60 seconds times its file's task count plus 60 seconds; each non-SF
process had a 90-second cap. Retries were disabled. Source and compiled-runtime
hashes were checked before and after the runs. All requested task/profile pairs
were collected, with no infrastructure errors, process timeouts or Lean panics.

## Changes and limitations

The fixed-budget comparison has 22 gains and 1 loss.
The IsaPlanner `prop_64` regression exhausts the candidate's 1,000 attempts at
depth two; it is a proof-search budget failure, not a wall-clock timeout.
The previous revision proves it in 6.704 seconds; the candidate exhausts its
budget in 7.133 seconds. This comparison retains that failure without retuning.

There are 1,593 common successes. Synchronous elaboration gives
summed declaration times of 1212.489
seconds before and 1192.011 seconds
after, with a geometric mean candidate/baseline ratio of
1.015 over 1,592 pairs
with positive times. These are single observations on shared hosts, so the
published improvement is proof coverage rather than a controlled speedup claim.

The four existing simple SF profiles (`simp_all`, `grind`, and oracle structural
induction followed by either) completed all 8,864 observations and solved
736 unique theorem goals. These
oracle profiles do not add generalization or the explicit fact portfolio used by
the stronger historical website baseline. The old website also used a different
2,190-goal SF cohort. Its baseline and committed-mode scores are therefore not
presented as current matched measurements.

## Validation and evidence

Before the implementation was pushed, a fresh build of all current
lean-waterfall case studies passed 124 Lake build jobs, `lake test`, 34 evaluation
harness tests (one expected skip), and 20 ACL2 harness tests. GitHub CI then
passed on Lean 4.30.0 and 4.33.1, including documentation checks and deployment.

Exact task selections, normalized rows, compressed raw dispatcher output,
source/runtime manifests, and the result-recomputation script are retained in
a local inductive-bench worktree at commit `9960e43ec14d0b30f77c26238fb6ce4a5b5989af`, under
`reports/waterfall-main-release-20260922/`. This public report contains the
aggregate results and measurement protocol.
