## Measurement

`f3c5ca3a1b4e5dc51ebeaa6967ebdb3b9b1459e6`. The previous-main column is
`dde8f2e304c4327661f7833695082d3ce4819385`, measured on the same fixed
inputs on September 22. The intermediate revision
`8d7d84bd08a756de7ee9c723169aee4091f9e3ef` was rerun against `v0.2.0`
goal by goal: both solve exactly the same 1,615 goals, with no gains or losses.

The 2,645-entry selection comprises 2,216 Software Foundations entries, 173

Fourteen SF entries are executable definitions rather than theorem tasks. The

The source inputs and task selection are the same as in the
[September 22 report](2026-09-22.md).

The existing harness replaces proofs while retaining the source theory.
Preceding or imported benchmark lemmas can be admitted assumptions. These
counts therefore measure individual goals in that context, rather than
constructing entire source developments automatically.

## Validation and evidence

The run used the configured `gh` cluster host, with 12 SF and 12 non-SF file
workers, one Lean thread per worker, synchronous elaboration
(`-DElab.async=false`), no retries, and the same task limits as the earlier run:
60 seconds per SF goal plus 60 seconds per file, and 90 seconds per non-SF task.
All 48 SF and 429 non-SF work units completed. The merged results contain every
requested task exactly once. Each normalized row agrees with its raw record;
there were no process errors, timeouts, or Lean panics. The SF dispatcher took
31.3 minutes and the non-SF dispatcher 19.1 minutes while running concurrently.

The exact selection, previous normalized results, source manifest, and source
archives are retained locally in the inductive-bench worktree under
`reports/waterfall-main-release-20260922/`. The `v0.2.0` source archive,
normalized and raw results, dispatcher logs, and recomputation scripts are
retained there under `reports/waterfall-v020-20260924/`. The comparison uses
the archived September 22 rows rather than rerunning the earlier revisions.
